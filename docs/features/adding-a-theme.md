# Adding a theme

A step-by-step guide for building a new built-in theme, with the problems the first themes
(Tron Legacy, Matrix, Synthwave, Amber CRT, Tron Ares) ran into and how to avoid them. Read
[theming.md](theming.md) first for how the system works; this file is the recipe.

## What a theme is

One `ThemeDefinition` value: ink and surface colors, nine semantic roles, a few token overrides,
three surface styles, a backdrop, a glow and three font faces, each with a dark and a light value.
Views never branch on the theme, so a new theme needs no view code. The only code beyond the
definition is a backdrop renderer, and only if the theme wants a new kind of moving background.

| File | Change |

| `Tinycast/Features/Theming/Model/ThemeCatalog.swift` | One line in `definition(for:)` |
| `Tinycast/DesignSystem/Theming/Backdrops/NameBackdrop.swift` | New file, only for a new backdrop kind |
| `Tinycast/DesignSystem/Theming/PanelBackdrop.swift` | One `case` in `BackdropRenderer.draw` (and `symbols` if it draws glyphs) |
| `Tinycast/Resources/Fonts/` and `Licenses/`, `NOTICE.md` | Only for a new bundled font |
| `Tests/appearance-test.swift` | Add the theme to the `adapts` block and the backdrop smoke loop |
| `Tests/backdrop-performance.swift` | Add the theme to the measured list |
| `docs/features/settings-file.md` | Add the raw value to the `appearance.visualTheme` row |
| `docs/features/theming.md` | A row per appearance in the backdrop budget table |
| `Tinycast.xcodeproj` | Regenerated by `xcodegen generate` whenever a file is added |

The Settings picker lists `ThemeID.allCases`, so the theme appears there with no UI work.

## Steps

1. **Design on paper first.** For each appearance pick: surface, ink, accent, a destructive red, a
   warning yellow or orange, a success color, link and find-highlight colors, the panel stroke and
   glow, and the backdrop colors (three slots: primary, secondary, tertiary). A theme must have a
   real light variant; it may be a calm "paper" version of the dark one (Amber's light is still
   paper grain).
2. **Add the `ThemeID` case** (raw value is what settings.json and backups store, so pick it once
   and never rename it) and its user-facing title.
3. **Write the definition**, copying the closest existing theme as a template (below).
4. **Run `./Scripts/run-tests.sh theme-test`.** It checks contrast for every theme in both
   appearances. Tune before going further (see "Contrast").
5. **Backdrop**: reuse an existing kind if one fits (Synthwave reuses Tron's grid floor). For a new
   kind, write a renderer following "Writing a backdrop renderer" below.
6. **Fonts**: use an existing `BundledFont` or a system design (`.system(.rounded)` and so on) if
   possible. A new font follows "Adding a font" below.
7. **Extend the tests**: add the theme to the `adapts` block and to the tuple list in the backdrop
   smoke loop in `Tests/appearance-test.swift`, and to the list in `Tests/backdrop-performance.swift`.
   If the light variant draws anything, add a Light pixel check like Amber's.
8. **Docs**: the settings-file value and the budget table rows.
9. **`xcodegen generate`**, then confirm the new files are in `Tinycast.xcodeproj/project.pbxproj`
   and that the regenerated project is staged with the commit (`git status` must be clean after).
10. **Verify**: `./Scripts/run-tests.sh`, a Debug build with no new warnings, `./Scripts/lint.sh`.
11. **Look at it** (see "Checking it by eye"), then measure (see "Cost").

## Definition template

```swift
import Foundation

extension ThemeCatalog {
    private static let nameAccent = RGBAPair(dark: RGBA(hex: 0x6FE3FF), light: RGBA(hex: 0x0086B3))

    static let name = ThemeDefinition(
        id: .name,
        ink: RGBAPair(dark: RGBA(hex: 0xDFF6FF), light: RGBA(hex: 0x0B2633)),
        surface: RGBAPair(dark: RGBA(hex: 0x05080C), light: RGBA(hex: 0xEAF4F8)),
        roles: ThemeRoles(
            accent: .rgba(nameAccent),
            onAccent: .rgba(RGBAPair(dark: RGBA(hex: 0x05080C), light: .gray(1))),
            primaryAction: .rgba(nameAccent),
            destructive: .rgba(RGBAPair(dark: RGBA(hex: 0xFF9A3C), light: RGBA(hex: 0xC2410C))),
            success: .rgba(RGBAPair(dark: RGBA(hex: 0x7CFFCB), light: RGBA(hex: 0x047857))),
            warning: .rgba(RGBAPair(dark: RGBA(hex: 0xFFB86B), light: RGBA(hex: 0xB45309))),
            progress: .rgba(nameAccent),
            link: .rgba(nameAccent),
            highlight: .rgba(nameAccent)),
        // Every custom theme restates these: system window gray and label white look wrong on them.
        overrides: [
            .windowSurface: .surface(dark: 1, light: 1),
            .terminalSurface: .surface(dark: 1, light: 1),
            .roomCardFill: .surface(dark: 0.94, light: 0.94),
            .chatText: .ink(dark: 1, light: 1),
            // All eleven code colors, tuned under "Contrast"; Tron's are a good starting point.
            .syntaxKeyword: .fixed(.hex(dark: 0x6FE3FF, light: 0x006B8F)),
            .syntaxString: .fixed(.hex(dark: 0xFF9A3C, light: 0xA33A0A)),
            // … syntaxNumber through syntaxDeleted, the same shape
        ],
        surfaces: ThemeSurfaces(
            panel: .solid(
                fill: .color(RGBAPair(dark: RGBA(hex: 0x05080C), light: RGBA(hex: 0xEAF4F8))),
                stroke: RGBAPair(dark: RGBA(hex: 0x6FE3FF, alpha: 0.55), light: RGBA(hex: 0x0086B3, alpha: 0.45)),
                glows: true),
            overlay: .solid(
                fill: .color(RGBAPair(dark: RGBA(hex: 0x0A1118), light: RGBA(hex: 0xF4FAFC))),
                stroke: RGBAPair(dark: RGBA(hex: 0x6FE3FF, alpha: 0.45), light: RGBA(hex: 0x0086B3, alpha: 0.35)),
                glows: true),
            control: .tintedGlass(
                RGBAPair(dark: RGBA(hex: 0x6FE3FF, alpha: 0.25), light: RGBA(hex: 0x0086B3, alpha: 0.18)))),
        backdrop: Backdrop(
            kind: .grid, primary: nameAccent,
            secondary: RGBAPair(dark: RGBA(hex: 0xFF9A3C), light: RGBA(hex: 0xC2410C)),
            tertiary: nameAccent,
            intensity: .init(dark: 0.55, light: 0.35), speed: 1, frameRate: 30, lightIsStatic: false),
        glow: Glow(
            color: RGBAPair(dark: RGBA(hex: 0x6FE3FF, alpha: 0.8), light: RGBA(hex: 0x0086B3, alpha: 0.5)),
            radius: .init(dark: 8, light: 3)),
        faces: ThemeFaces(display: .bundled(.orbitron), body: .bundled(.exo2), mono: .system(.monospaced)))
}
```

Choices that matter:

- **Panel**: always `.solid` (theme-test requires it so contrast is computable). Use
  `.verticalGradient(top:bottom:)` for a gradient (Synthwave).
- **Overlay and control**: `.solid` or `.tintedGlass`. Tinted glass becomes solid under Reduce
  Transparency on its own.
- **Glow**: radius 0 means no glow. A light radius of 0 is fine (Amber). Glow turns off under
  Increase Contrast automatically, and extensions never draw it.
- **`lightIsStatic: true`** when the light variant is a texture, not motion: the timeline draws one
  frame and stops, so Light costs nothing.
- **`frameRate`**: 30 for line-based backdrops; glyph-heavy ones can drop to 24 (Matrix).

## Contrast

`theme-test` requires primary text at 4.5:1 and secondary text at 3:1, measured against the panel
fill with each backdrop color composited on top at full intensity, then the scrim. When a check fails:

1. Lower that appearance's backdrop `intensity` in 0.05 steps (Amber's dark went from 0.5 to 0.4).
2. Only if intensity 0.15 still fails, change the ink.

Secondary text in dark is usually the tightest margin (Synthwave dark is 3.30, Amber dark 3.30).
Record the final ratios in the PR.

Code colors have their own checks. Every one of the eleven `syntax*` tokens needs 4.5:1 on a code
card over the window page and 3:1 on the worst panel pixel, the same floor as secondary text.
Keyword, string, number, comment and type must also sit at least 15 CIE76 units from the ink and 12
from each other, and inserted and deleted diff lines 40 apart. A one-hue theme meets that by varying
brightness and leaning a little toward neighboring hues (Matrix's strings go yellow-green, its types
teal). Diff lines may leave the theme's hue, since red and green carry the meaning there. When the
worst-pixel check fails in dark, lighten the color toward white before reaching for another hue;
Synthwave and Ares need it most, because their backdrops are the brightest.

## Writing a backdrop renderer

Shape it like the existing ones in `DesignSystem/Theming/Backdrops/`:

```swift
import SwiftUI

/// One line on what it draws.
enum NameBackdrop {
    static func draw(
        _ backdrop: Backdrop, in context: inout GraphicsContext, size: CGSize, time: Double, dark: Bool
    ) {
        let line = BackdropRenderer.color(backdrop.primary, dark: dark)
        // Positions are pure functions of `time` and BackdropRenderer.mix/unit(index).
    }
}
```

Rules, each learned the hard way:

- **Colors come from `BackdropRenderer.color(_:dark:)`**, never `ThemePalette.color(...)`. The
  latter builds a new dynamic `NSColor` every call, which is about 60 allocations a second per color
  in a renderer.
- **No actor isolation on the renderer**, and nothing in it may call main-actor code. Plain enums
  are nonisolated in this project. This matters doubly for any `NSColor(name:)` provider closure:
  AppKit can resolve those off the main thread, and a main-actor closure traps there. That shipped
  once in a draft and was caught in review; any provider must be `@Sendable` and call only
  `nonisolated` helpers.
- **Stateless**: no stored properties, no caches, no `@State`. Every position, length, speed and
  glyph choice comes from `time` and a hash of an index (`BackdropRenderer.mix`, `unit`). Gate
  "which columns are active" by hashing the column index, not by storing anything.
- **Anything that loops must loop seamlessly.** Synthwave's sun bands first sized each band by its
  index, so every band jumped thicker at the wrap. Size and fade things by their continuous position
  instead, so an element enters at zero and leaves past the clip.
- **Don't reuse a name inside one function.** A `let top` color and a `let top` y coordinate in the
  same `drawLayer` closure was a compile hazard; name things `sunTop`, `bandTop`.
- **Glyphs go through `Canvas` symbols**, resolved once, and drawn with `context.resolveSymbol(id:)`.
  Use a single `ForEach` with distinct tags (Matrix uses body tags `0..<n` and head tags `1000+i`);
  two `ForEach` blocks over the same indices crash with "child view IDs must be unique".
- **Draw count is the cost.** About 480 glyph draws per frame put code rain near 10% of one core
  live; about 300 at 24 fps is the shipped compromise. Lines and paths are cheap (Tron's grid is
  well under 1 ms per frame).
- **Time is wrapped to an hour** by `PanelBackdrop`; any periodic motion should divide cleanly or
  tolerate a once-an-hour jump.

Then add the `case` to `BackdropRenderer.draw` (and to `symbols` if it draws glyphs), and the
`BackdropKind` case to the model.

## Adding a font

1. Pick an SIL OFL font from Google Fonts. Download from
   `https://raw.githubusercontent.com/google/fonts/main/ofl/<family>/` into a fresh temp directory,
   with `OFL.txt` from the same folder.
2. Confirm the family name CoreText reports (it is not always the file name; "Exo 2" has a space):
   register the file process-scoped with `CTFontManagerCreateFontDescriptorsFromURL` in a small
   `swift` script outside the download folder, and print `kCTFontFamilyNameAttribute`.
3. Copy the `.ttf` files into `Tinycast/Resources/Fonts/` and the license to
   `Tinycast/Resources/Fonts/Licenses/<FamilyNoSpaces>-OFL.txt` (use `command cp -f`; `cp` is aliased).
4. Add a `BundledFont` case with `family` and `files`. `license` derives from the family.
5. List it in `NOTICE.md`.
6. `theme-test` fails if a listed file or license is missing.

Single-weight fonts (Share Tech Mono, Audiowide, VT323) render every weight as Regular; that is
acceptable for display faces but worth knowing. For a body face, prefer a variable font or ship the
weights the UI uses (IBM Plex Mono ships Regular, Medium, SemiBold, Bold), and check in the app that
Medium and SemiBold look distinct from Bold. The test harness registers fonts process-scoped, which
is not the same path as the app's `ATSApplicationFontsPath`.

## Checking it by eye

Agents cannot see the screen, and must not open windows on Devon's machine to try (no hosted-window
probes, no app launches). The visual pass is Devon's:

- Settings → General → Theme → the new theme, then back to Default (Default must look unchanged).
- Light and Dark, each over a light and a dark wallpaper: palette, a note, a menu, a dialog, both
  HUDs, the quick action result and the chat window.
- Text legible over the backdrop at its brightest; motion smooth with no jump at the loop.
- Increase Contrast on: hairlines get stronger, glow turns off. Reduce Motion: backdrop holds still.
  Reduce Transparency: tinted glass goes solid.

## Cost

The hard rule is zero CPU while the palette is hidden; the backdrop pauses on hide and occlusion,
so this holds as long as the renderer is drawn only through `PanelBackdrop`. While the palette is
open, Devon accepts more than the 5% to 8% target, since it is only open for seconds.

- `Tests/backdrop-performance.swift` (`./Scripts/run-tests.sh backdrop-performance`) times the draw
  offscreen. It is a rough guide: it overstates glyph-heavy backdrops (it re-resolves symbols every
  frame) and leaves out compositing.
- The live number comes from Devon running `TINYCAST_PROCESS=Tinycast Scripts/measure-backdrop.sh`
  three times (palette hidden, open, hidden) with the theme active. The open figure includes the
  rest of the palette (Tron measured 11.1% open, 0.1% to 0.3% hidden). Record it in the budget table.

## Things that do not need doing

- No view changes: surfaces, rows, menus, AppKit text, the caret and extension tints all follow the
  active theme already.
- No settings or backup work beyond the docs value: `ThemeID` is already a settings.json raw value
  and is carried by backups.
- No Increase Contrast work: hairline raising and glow-off are automatic for every non-Default theme.
